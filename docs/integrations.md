# Dating API research and browser tools

Reviewed October 11, 2026. Keep Fix Cut reviews uploaded photos, pasted prompts, and optional voice recordings. Users copy rewrites and upload edited photos into their dating apps themselves. The app does not sign in to dating accounts or call dating APIs. A teardown uses the explicit **Run teardown** action and its privacy notice.

## What the researched sources actually support

The API paths below are observations from source code and documentation, not supported KeepFixCut connections or verified live requests. No dating-account credentials were collected and no external repository code or paid actor was run. GitHub freshness dates are `pushed_at`, not evidence that an API still works.

| Source | Authentication and actual operations | License and freshness | Production decision |
| --- | --- | --- | --- |
| [Miguelo981/tinder-api](https://github.com/Miguelo981/tinder-api) | Explicitly unofficial TypeScript client. Uses `X-AUTH-TOKEN` plus a persistent device identifier; also implements SMS verification and optional email verification. Its `profile()` reads the authenticated user's profile; `updateProfile()` calls `POST /v2/profile` for bio/discovery settings, and `updateUserProfile()` calls `POST /v2/profile/user` for recommendation preferences. The README describes some preference controls as paid features. It also supports searching, swipes, matches, messages, and boosts. | [MIT](https://github.com/Miguelo981/tinder-api/blob/main/LICENSE); last repository push July 23, 2026. | No live client or sign-in flow. Users supply photos and profile text directly to the scanner. |
| [ReedGraff/HingeSDK](https://github.com/ReedGraff/HingeSDK) | Explicitly unofficial Python client. Uses an existing bearer token, session ID, and user ID; experimental SMS login also uses device/install identifiers. [Implemented methods](https://github.com/ReedGraff/HingeSDK/blob/main/hingesdk/api.py) include public users/content, recommendations, standouts, settings, account information, likes, and messages. Read paths include `/user/v2/public`, `/content/v1/public`, `/content/v1/settings`, `/user/v2/traits`, and `/store/v2/account`. There is no implemented own-profile photo/prompt update or reorder API. | README claims MIT, but the inspected repository tree has no standalone license and GitHub did not identify one. Clarify licensing before reusing source. Last push November 22, 2025. | Do not ship this client. [Its request code](https://github.com/ReedGraff/HingeSDK/blob/main/hingesdk/client.py) prints request headers and responses, including bearer credentials; the login example also prints account credentials. Use explicit local bio/prompt inputs instead. |
| [radian-software/squeaky-hinge](https://github.com/radian-software/squeaky-hinge) | Reverse-engineered Android inbox/notification client. [Authentication](https://github.com/radian-software/squeaky-hinge/blob/main/auth.py) uses install registration, a Google phone-verification flow, and a Hinge bearer token; credentials are saved in `hinge_creds.json`. [Conversations](https://github.com/radian-software/squeaky-hinge/blob/main/conversations.py) uses `/message/authenticate`, then SendBird group-channel/message endpoints. This is an inbox tool, not an own-profile editor. | [MIT](https://github.com/radian-software/squeaky-hinge/blob/main/LICENSE.md); last push March 27, 2026. | Do not ship. Its logs can contain credentials, phone numbers, sessions, and conversation contents. It offers no needed profile-edit operation. Its README warns that the reverse-engineered API may break. |
| [b1rdmania/hinge-profile-optimizer](https://github.com/b1rdmania/hinge-profile-optimizer) | Agent instructions and supporting profile-audit references. No account authentication, live API adapter, own-profile read/write endpoint, or MCP server is implemented. Users supply photos/screenshots and apply suggestions themselves. | [MIT](https://github.com/b1rdmania/hinge-profile-optimizer/blob/main/LICENSE); last push September 1, 2026. | Useful research for discovery questions, specific prompt feedback, and a manual implementation checklist. Preserve attribution if copying material. Independently verify statistical and algorithm claims before showing them as facts. |
| [Apify: datapilot/tinder-profile-scraper](https://apify.com/datapilot/tinder-profile-scraper/api) | Community actor requiring an Apify account and API token. Takes usernames and returns dataset records. Documented actor paths include `POST /v2/actors/datapilot~tinder-profile-scraper/runs` and `POST /v2/actors/datapilot~tinder-profile-scraper/run-sync-get-dataset-items`. This is not authenticated own-profile management or a Bumble connector. | Marketplace service, not a verified open-source licensed client. Listing showed $8/month plus usage on the review date; pricing can change. | No paid runs, scraping, actor token fields, or automated uploads. |

The [Tinder README](https://github.com/Miguelo981/tinder-api/blob/main/README.md) and [profile response type](https://github.com/Miguelo981/tinder-api/blob/main/src/interfaces/profile.ts) support the distinction between authenticated profile data and recommendation results. Its [client](https://github.com/Miguelo981/tinder-api/blob/main/src/tinder.ts) and [routing constants](https://github.com/Miguelo981/tinder-api/blob/main/src/constants.ts) implement the authenticated read as `GET https://api.gotinder.com/v2/profile`. Source-level capability does not establish provider permission or a stable third-party API contract.

Hinge's [Terms of Use](https://hinge.co/terms) require written consent for third-party applications interacting with the service and access to its API. Its [note on third-party automated tools](https://help.hinge.co/hc/en-us/articles/49657802257683-Note-on-Third-Party-Automated-Tools) says unauthorized automation can lead to account bans. A user's consent to improve their profile does not establish that provider permission.

No verified authorized production Bumble connector was found in these sources. Bumble users supply their photos and profile text directly, then apply changes in Bumble themselves. Its [current terms](https://bumble.com/en/terms) remain the provider reference. This research does not claim that no partner API can exist.

## Useful public libraries

| Repository | License and reviewed freshness | Concrete use |
| --- | --- | --- |
| [nodeca/pica](https://github.com/nodeca/pica) | [MIT](https://github.com/nodeca/pica/blob/master/LICENSE), version 10.0.3; last push August 15, 2026. | Browser-only high-quality photo resizing. Use the pinned, self-hosted module and JavaScript feature mode under the current content security policy. Do not copy original EXIF/GPS metadata into exported images. Its [documentation](https://github.com/nodeca/pica/blob/master/README.md) explains worker/WASM features and browser memory limitations. |
| [fengyuanchen/cropperjs](https://github.com/fengyuanchen/cropperjs) | [MIT](https://github.com/fengyuanchen/cropperjs/blob/main/LICENSE); v2.3.0 released October 7, 2026; last push October 8. | Optional future upgrade for adjustable crop handles, aspect ratios, keyboard movement, and touch manipulation. [Selection APIs](https://fengyuanchen.github.io/cropperjs/api/cropper-selection.html) export a canvas for local image saving. The current bench already crops; adopt this only if a tested UX improvement justifies replacing it. |

Pica is vendored with its license under `public/vendor/`; `scripts/vendor.mjs` copies the pinned package artifacts. No dating API SDK is a runtime dependency. Future live integrations require provider authorization, a reviewed account-data architecture, and representative contract fixtures.
